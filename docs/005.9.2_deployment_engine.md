# 005.9.2 EXACT-SHA DEPLOYMENT ENGINE

## Release Identity
JobPilot production deployments are strictly bound to an explicit 40-character Git commit SHA.
Mutable tags such as `latest` or `production` are fundamentally unsafe for production and are rejected by the deployment pipeline.

## Immutable Image Naming
The FastAPI production image must be built and referenced precisely as `jobpilot-fastapi:<commit-sha>`.
This ensures that the running artifact is 100% deterministic and traceably matches the repository state.

## Deployment Preflight
Before executing any deployment rollout, the `scripts/deploy.py` engine performs comprehensive preflight checks:
- Verifies the SHA matches a strict 40-character hex regex.
- Ensures Docker CLI is available.
- Asserts that minimum free disk space is met (avoiding zero-byte outage cascades).
- Validates that `docker-compose.production.yml` renders safely without YAML/variable errors.
- Inspects the local Docker daemon to confirm the target image artifact exists and correctly targets the ARM64 architecture. An ARM64 mismatch FAILS CLOSED by default, terminating the pipeline immediately. The `ALLOW_ARCH_MISMATCH=true` environment variable exists exclusively as a local/synthetic testing override.

## Rollout & Verification
1. Records intended metadata (current/previous SHA, timestamp).
2. Triggers `docker compose up -d --no-build` non-destructively.
3. Actively polls `docker compose ps` until FastAPI becomes healthy.
4. Cryptographically verifies that the running container's image ref and `$APP_COMMIT_SHA` environment variable identically match the target SHA.
5. Commits successful metadata to `.current_release.json`.

## Idempotency
Requesting deployment of a SHA that is already verified as running and healthy will gracefully exit without triggering container rebuilds or network bounces.

## Out of Scope
Database migration execution, automated database rollbacks, DNS management, and TLS provisioning remain out of scope for this milestone (005.9.3+).

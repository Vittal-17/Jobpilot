# 005.9.3 MIGRATION + BACKUP SAFETY

## Core Philosophy
Database migrations are strictly separated from application startup. A FastAPI container boot must never execute `alembic upgrade head`. Migrations are orchestrated deterministically via the deployment engine (`scripts/deploy.py`), governed by rigorous safety gates.
We strictly do NOT perform automatic database rollbacks (downgrades), as doing so destructively modifies schema states dynamically, which requires human supervision in production.

## Backup Strategy
- Prior to any Alembic invocation, a pre-migration backup is enforced.
- **Format:** PostgreSQL Custom Format (`pg_dump -Fc`), offering optimal compression, atomic logical restore semantics, and portability on ARM64 environments without mandating heavyweight block-level snapshots.
- **Naming:** Deterministically generated as `backup_<sha>_<timestamp>.dump`.
- **Integrity Validation:**
  - Size check (must be non-empty).
  - SHA-256 checksum generation and binding in metadata.
  - Logical integrity validation (`pg_restore -l`) proves the custom format envelope is sound.

## Restore Verification
To guarantee restorability without overwriting the live database, `deploy.py` streams the `.dump` artifact into a strictly isolated, ephemeral PostgreSQL container (`jobpilot_verify_db_*`). It executes a **full archive restore** utilizing `--no-owner --no-privileges` to prove the dump is structurally coherent and not corrupted. The live production container is intentionally bypassed during this phase.
*Exit Status Autonomy:* ANY non-zero return code from `pg_restore` is treated as a fatal failure, strictly halting the pipeline. Zero return codes with standard stderr warnings are accepted.
*Note on Testing:* In local Python CI runs, Docker subprocesses for restore verification are securely mocked to validate boundary state transitions. Actual Docker container spin-up and teardown natively executes on the real VPS target via `subprocess.run` as part of the exact-SHA choreographic pipeline.

## Migration Procedure
- The engine executes migrations via the distinct `migration` service profile in `docker-compose.production.yml`.
- **Pre-flight:** Validates DB connectivity and Alembic config.
- **Execution:** Runs `alembic upgrade head`.
- **Post-flight:** A subsequent `alembic current` call is executed, followed by a raw `psql` connectivity test to ensure the database layer actually survived the migration.

## Failure Behavior & Manual Restore
- **Migration Failure:** The rollout stops. The metadata phase transitions to `failed`. The application rollout is suppressed.
- **Application Failure Post-Migration:** The release identity verification fails, but the schema remains at the migrated head.
- **Manual Restore Procedure:**
  WARNING: Restoring data is destructive to current state!
  Command: `docker compose exec -T db pg_restore -U u -d app_db --clean --if-exists --no-owner --no-privileges < /path/to/backups/backup_<sha>_<timestamp>.dump`
  *Role Context:* The `--no-owner --no-privileges` flags are explicitly documented for restoring to avoid role-mapping conflicts if the target environment's ownership deviates, preventing non-fatal warnings from failing the restore gracefully. The container `POSTGRES_USER` natively resumes ownership.
- The sole recovery backup is NEVER automatically deleted.

## Disk Safety & Lock
- Pre-flight verifies `MIN_FREE_SPACE_BYTES` (2GB default) exists.
- A POSIX file lock (`.deploy.lock`) prevents multiple deployment engines from corrupting the DB simultaneously.
- **Kernel-level flock:** The lock uses a persistent file and advisory kernel locks (`fcntl.flock`). The file is never deleted.
- **No stale lock stealing:** If a process dies, the kernel automatically releases the advisory lock. PID metadata within the file is purely informational and is never used to forcefully break a lock.

## Metadata State Machine
Transitions deterministically: `prepared` -> `backup_verified` -> `restore_verified` -> `migration_started` -> `migration_succeeded` -> `rollout_started` -> `rollout_succeeded` (or `failed` at any point).
